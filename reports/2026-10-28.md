# Cloudflare 新发布观察 · 2026-10-28

这次从官方 changelog 与博客直接寻找变化，再追到具体接口和限制。资料发现覆盖 10 月 20–27 日；本篇记录 10 月 28 日查阅时的判断。重点是已有系统升级后还能否读回旧状态、中断后会重做什么，以及一个配置究竟约束哪一段。

当前[手册](../guides/handbook.md)、服务页与[实施参考](../reference/implementation.md)承接使用说明。此前报告、三册首发编排、已分享的更新增补与冻结 PDF 保留原日期；本轮没有把局部核查写成全书重新验收。

## 01 / 恢复 run、恢复文件、恢复对话是三件事

Computer **v0.7.0** 为 JavaScript backend 增加中断恢复：默认 `fail` 让 run 失败，`restart` 重跑调用，`replay` 复用 journal 已记下的结果再继续。**外部动作成功但结果尚未记下**仍可能再执行；稳定 `callId` 可接外部幂等，不能重复的调用用 `unsafeToRepeat()` 让中断停在失败处。[S175]

等待批准的 `ctx.interrupt()` 由应用以 `pending()`／`respond()` 接回。答复会重新进入函数，批准前的代码也要能重做；恢复通常由下一次 runtime 调用触发，主动恢复需要 DO alarm。它仍是 experimental，replay 会缓冲 `fetch`、默认每个 body 限 1 MiB，不兼容的 runtime／package 变化可能使旧 run 失败。[S176]

两个升级还要先处理存储：

| 变化 | 不能忽略的接续条件 |
|---|---|
| Think／Agent Skills 改用 Computer（10-20） | 旧 `@cloudflare/shell`／`createExecuteTool` 停止维护，新旧表无自动文件迁移；空工作区不表示旧数据已删除。[S177] |
| Agents SDK 0.30.0／Pi 1.4（10-22） | 反复崩溃任务可停放为 `parked`；会话 schema 升级后 Pi 1.3 无法打开，回退代码不恢复旧 schema。[S178] |

这些机制与 Browser 的活会话重连、SQLite 教学例子的租约恢复分别阅读。[Agent runtime](../services/agent-runtime.md)给出使用条件；本书没有因此安装 SDK、迁移工作区或重启云端 agent。

## 02 / provider 合并与推理隔离，分别检查

10 月 21 日，Agents SDK 的 `createAI` 统一 Workers AI、Gateway catalog、dynamic routes 与 vendor models；旧 `workers-ai-provider`／`ai-gateway-provider` feature frozen、deprecated，AI Search 使用独立 `ai-search-provider`。外部连接的旧 `apiKey` 改为 `apiToken`。[S179]

fallback 在模型尚未输出时失败才试下一款；binding 的 catalog／dynamic route stream resume 解决断流续读，不是任意工具调用的恢复保证。迁移应保留实际模型身份、凭据、错误与用量观察，说明进入[API 维护](../reference/api-maintenance.md#模型-provider-迁移保留调用条件)。[S180]

10 月 26 日的 GLM-5.3 事故披露则有不同时间线：Workers AI 的 `@cf/zai-org/glm-5.3` 于 **8 月 27 日至 9 月 9 日**存在跨请求 KV cache 暴露，官方称 **9 月 9 日**已修复恢复、其他 Workers AI 模型未受影响。问题来自上下文与 prefill KV pool 不匹配叠加引擎拒绝路径缺陷。这里记录官方披露，不把它写成当前仍未修复，也不推广到其他同名模型部署。对使用者的启示是验收内容与请求隔离，不能只看 HTTP 200。[S200]

## 03 / Workflows 地点与 D1 恢复都有明确边界

10 月 27 日 Workflows 支持 `eu`、`us`、`fedramp` jurisdiction，要求 Wrangler **4.152.0+**。约束在创建时固定；已有对象不匹配时上传前失败，换名字创建或删除重建都须安排实例迁移，删除会删除实例。[S182]

约束覆盖实例运行与持久数据，**不覆盖辖区外的设置存储，也不限制管理请求来自哪里**；local dev 忽略该字段，移除配置不会解除原 jurisdiction。它能支持一段数据路径的地点要求，不能独自证明整个应用满足法规或合同。[S183]

10 月 23 日 D1 undelete 限为删除后 **7×24 小时内**，不能套用现存数据库 Time Travel 的 30 天。API 还明确：恢复后不能用 Time Travel 回到此次 undelete 时刻或更早。独立导出、数据库身份与删除时间仍要保存，具体接口见[误删恢复说明](../reference/implementation.md#误删-d1-之后还能恢复吗)。[S184] [S185]

## 04 / 入口迁移、路径匹配与登录页面

| 更新 | 具体使用条件 |
|---|---|
| 产品 MCP `/sse` 退役（10-22） | 旧地址返回 **410 Gone**，改为该服务器的 `/mcp`；旧 `/sse` 登录需重新授权。已经使用 `/mcp` 的连接不受影响。[S181] |
| Tunnel URL 归一化（10-22） | `cloudflared` 2026.10.0+ 支持；当前默认关闭，**2027-01-25 起的新版本**默认开启。归一化用于含 Access validation 的 ingress 匹配，送到源站的路径不变。[S190] |
| Tunnel Read And Monitor GA（10-22） | 只给选定 Tunnel 的读取和远程日志；旧 Read 角色不包含日志串流，不必为排障授写权限。[S191] |
| Access 自定义页（10-27） | HTML／Liquid 用于登录、身份拒绝、forbidden 与命令行批准页；应用指定或账户默认可复用模板。[S192] |

Access 模板不提供自定义 JavaScript 或认证表单；保存的模板无法安全渲染时回退内置页，策略结果不变。编辑器没有渲染预览或 Download，模板应另存副本；共享模板发布影响多个应用，需实际走一遍允许、拒绝与回退。[S193]

本轮只补使用边界，没有改本机 Tunnel、MCP 客户端或 Access 配置。

## 05 / 发布工具的默认值也会改变交付内容

Wrangler **4.150.0+** 的 deploy、versions upload、preview 默认生成并上传 source maps；`cf deploy` 也默认上传，Cloudflare Vite plugin **1.64.0+** 默认生成。原始路径与源码的上传范围应在部署前核对；退出方式分别是 Wrangler 的 `upload_source_maps: false`、cf／Vite 的 Worker `build.sourcemap: false`。自定义 build 中不能解析的 map 默认跳过，显式 `true` 才让上传失败。[S186]

Workers Builds 新支持 `packageManager` 精确选择 npm，`engines.npm` 不选版本。[S187]构建镜像 10 月 23 日又修补 eMudhra 信任链；使用旧 Bun、自定义证书变量或自带 CA 的下载工具仍须逐项核对，锁定 runtime 不能自动证明 CA 已更新。[S188]

Sandbox 另分两代：0.x 的修补是 SDK **0.12.14** 与匹配镜像；1.x 由自己的镜像管理信任链，重建后还要替换运行中的旧容器。旧 snapshot 会带回旧镜像，修补成果不能只从 Worker 部署成功推断。这里只整理官方处理条件，没有执行镜像重建或破坏性清理。[S189]

## 06 / 把请求身份、属性与导出范围接起来

| 更新 | 用于什么、不能推断什么 |
|---|---|
| custom spans 新 API（10-26） | `spanContext()` 取 ID，`updateName()` 改名字，`setStatus()` 进 OTLP 导出；dashboard 还不显示 status。[S194] [S195] |
| SQL introspection（10-27） | `include_attributes=true` 发现**前七天**的 JSON keys 与类型，返回 `attributes`；旧名称 deprecated 但兼容，未出现的 key 不代表不存在于历史。[S196] |
| 账户级 HTTP request Logpush（10-21） | 一个 job 覆盖账户 zones，`ZoneName` 标识来源；custom fields 仍各 zone 管理，迁移前核对重复交付。[S197] |

当前[观测页](../services/observability.md)接回调查步骤；新接口没有改变哪些日志应保存、谁能读取与保留多久的责任。

## 07 / WAF 看见响应，不等于撤销源站动作

10 月 21 日全事务检测把请求与响应关联，响应规则可在交付前阻断源站响应。所有计划包含 Free 都有入口，当前最多三个 custom response rules，支持 Log／Block；可用字段随计划变化，不能任意按 response body 编写规则。源站已经执行的动作不会被响应阻断撤销。[S201]

10 月 25 日针对 Brotli／Next.js 的两个紧急 Managed Rules 默认 **Log**，不是默认阻断。既有 ruleset-level Block override 仍可能将其变成拦截，并误伤合法的 Brotli 请求 body 或 `/_next/image`。调查时看实际命中与最终动作，不能只看“规则已启用”。[S202]

## 08 / 另外三项变化，留给命中的调用方

| 变化 | 何时需要接回项目 |
|---|---|
| Advanced Nameservers 类型（10-26） | 约七天滚动切换 `cloudflare.advanced`；封闭 enum 或同时写 `foundation_dns` 的代码要检查，新旧字段不能冲突。不要求 zone 迁移。[S198] |
| Flagship structured context（10-23） | 支持对象、数组、null，nested path 与数组成员条件；相关 OpenFeature SDK **0.6.0+** 走 JSON POST。已有扁平输入不因此失效。[S199] |
| Basin SQL OFFSET（10-21） | `LIMIT`／`OFFSET` 可分页，配合唯一列 `ORDER BY` 稳定顺序；它不替代遍历期间数据变化与部分失败处理。[S203] |

本轮没有把 Radar 改版、CTF、企业认证和客户端每个修复项逐一扩成服务教程；它们没有改变本书现有例子的执行合同。eMudhra 相关的构建／Sandbox 条件已纳入，设备端客户端仍按实际平台和发布渠道核对。本篇是有范围的官方资料审阅，不是全部 Cloudflare 产品的认证。

## 09 / 费用复访：一个问题已解决，两个疑点还在

| 本次直接复看的来源 | 10 月 28 日能确认的状态 |
|---|---|
| Observability／Workers Logs | 仍于 **12-01** 切换；Paid 含 50 GB 摄取与 10 GB-month 存储，官方算例已改为存储 **$1.00**、总额 **$7.25**；此前不追溯，届时仍可查询的旧数据开始计存储。[S100] [S111] |
| AI Search | 仍 **11-01** 起算；chunk overlap 重复计摄取 tokens，OCR 还含 image processing，生成与 query rewriting 另计。临近生效先按实际查询类型和分块估算。[S10] |
| Artifacts | 价格页 **10-14** 与博客 **10-15** 冲突仍在；按已进入公开计费期预算，没有核对实际扣款。[S08] [S07] |
| CF 托管 Clef 与 CF Jev 目录 | 三款 Clef 的价／窗口及 Jev 的 $0.042／M、32,000 目录窗口未发现变化；其他 provider 与性能未重核。[S17] [S18] [S124] [S73] |
| Clairic | 模型卡仍同时写 65,536 context 与 8,192-token pass，未解释两者关系；保留疑点，不自行承诺长材料完整读取。[S164] |

只有实际查阅的来源更新日期。维护 `due` 队列中的旧期限继续提醒尚未复核部分；这轮网页和离线检查不证明账户开放、真实模型质量或账单结果。
