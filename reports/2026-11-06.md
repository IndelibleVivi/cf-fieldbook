# Cloudflare 新发布观察 · 2026-11-06

这次接着 10 月 28 日的资料寻找变化，发现范围覆盖 10 月 28 日至 11 月 5 日，查阅截止 11 月 6 日。最先改变判断的是 AI Search 的收费延期；接下来是几种容易混为一谈的保证：让旧代码多运行一会儿、重试一次对象调用、保存一段流式进度，以及停止浏览器工具。它们都不能替应用撤回已经发生的动作。

当前[实践手册](../guides/handbook.md)、[Agent runtime](../services/agent-runtime.md)、[模型接入](../services/decision-models.md)和[实施参考](../reference/implementation.md)已承接相关条件。[10 月 28 日观察](2026-10-28.md)、首发三册、独立增补和已冻结 PDF 保留原范围。

<!-- chapter: billing -->

## 01 / AI Search 延期收费，也改变了默认同步节奏

11 月 2 日公告将 AI Search 计费起点从 **11 月 1 日延期到 12 月 1 日**，并明确在这之前不收 AI Search 使用费；单价与包含量不变。不能因为旧日期已经过去，就推定 11 月已收费。生成、外部模型及其他产品仍有各自条款，未读取真实账单。[S204] [S10]

默认同步间隔同时由 **6 小时变为 24 小时**，仍可在实例设置或 API 的 `sync_interval` 中选择 15 分钟至 24 小时。资料更新后迟迟搜不到时，除了入库和 tokenizer，也要核对实际同步设置与任务状态；默认值变化不证明每个既有实例都已改变。[S204]

对于本书的资料架扩展设计，读取资格与撤回仍由应用先控制，不能等下一次定时索引才停止返回私有内容。完整计量与检索条件见[搜索页](../services/search.md)。

另一项日期不能直接跟着改：11 月 6 日复看的 **Artifacts 价格页写 11 月 12 日开始计费**，旧 changelog 仍写 10 月 14 日、博客仍写 15 日。本书保留三处说法及查阅时间，不再将“已进入计费期”当作当前定论；现行单价可用于预留预算，历史用量及实际起算未核验。原报告中的旧冲突保留历史身份。[S08] [S135] [S07]

Observability／Workers Logs 则定向复看后数值未变：新方案仍在 **12 月 1 日**切换，Paid 包含 50 GB 摄取与 10 GB-month 存储，算例仍为 $6.25 + $1.00 = **$7.25**。这项固定费用快照单独推进至 11-06；没有读取账单或重核所有观测机制。[S100] [S111]

## 02 / Pi 1.5：可见进度与落盘进度之间有一秒

11 月 3 日 Agents SDK **0.33.0** 接入 Pi **1.5**。流式答案和工具输出即时可见，但默认在最多约 **1 秒**内批量保存；崩溃可能丢失这段尚未落盘的进度。`settings.progress.persistWithinMs` 可调整窗口，设为 `0` 改为逐次写入，代价是更多存储写入。[S209] [S105]

| 旧调用或状态 | 新一版应怎样接续 |
|---|---|
| `session.events()` | 改为 `session.watch()`，先取完整当前 view，再接变化；对象重启后重新开 watch |
| 为继续工作再追加一条消息 | idle session 可用 `session.continue()`，先查原 `operationId` 的结果，保留独立 continuation receipt |
| `parked`、`retry()` | 已移除；连续中断达到 `settings.restartLimit`（默认 5）后结束该任务，模型任务可得到 `unanswered / restart_limit` |
| 直接回滚到 Pi 1.4 | 1.5 写入的会话不能由 1.4 读取；修复部署应向前推进 |

`defaults.maxTurns` 限制新 session 的工具轮数。`wait(operationId, signal)` 的等待被取消，不等于工作停止；`abort()` 要等 session idle，忽略 abort signal 的自定义工具仍可继续运行。工具副作用仍须按自己的幂等或结果查询契约处理。[S209] [S105]

公告的吞吐与写入改善来自特定 SQLite benchmark，不作为本仓库或任意应用的性能保证。本轮没有安装 SDK、迁移会话或测模型。

## 03 / DO 的延迟更新与自动重试，解决的是两种中断

10 月 30 日起，Durable Objects 默认可延迟采用新代码最多 **300 秒**，等 active object 休眠；到期仍活跃则 reset 并采用最新部署。`code_update_strategy` 可显式选 `deferred` 或 `immediate`，但延迟是 best effort，runtime 更新等原因仍可提前 reset。发布后马上调用 DO 的工具也不能假定它已在新代码上。[S207] [S208]

连续部署各自启动 delay timer；先到期的 timer 让对象采用当时最新部署，不保证每个中间版本都运行过。此策略与 Workers 例行 runtime 更新的连接排空、Pi 的持久 checkpoint 是三项不同机制。[S208]

11 月 5 日的 DO 自动重试覆盖 stub 的 `fetch()` 和 RPC：默认首次加 **4 次重试**，不在首次开始 **10 秒**后启动新重试。它重试标有 `.retryable` 的特定传输失败，不重试应用抛出的错误、`.overloaded` 或普通 HTTP `500` 响应。[S205] [S206]

连接结果未知时，平台沿用同一请求身份；对象已收到首个调用则拒绝重复执行。只有开发者用 `retryable()` 标记方法，才允许这种情况下再执行；“把数量设为 3”可设计为幂等，“再加 1”不能直接套用。工具和外部服务是否产生两次动作仍由应用核对。[S206]

Stream body、含 stream／stub／function 的 RPC 参数、promise pipelining 等不在可重发范围。`retryable()` 和 stub 的 `retry` 配置需要 Wrangler **4.158.0+**；外层已有重试的程序要把平台内层次数计入总预算。精确限制见[实施参考](../reference/implementation.md#durable-objects-自动重试不等于任意动作可重放)。[S205] [S206]

## 04 / 私有预览、取消调用与浏览器恢复分别检查

Agents SDK **0.31.0+** 的 Browser internal hostnames 可以把 `preview.internal` 指向 agent 的 Workspace、Sandbox dev server 或 service-bound Worker，不用发布公共 URL。映射目标可按 schema 校验并跨 turn、浏览器重启与 redeploy 保存；这不是保存旧 tabs、cookies 或运行中的进程。[S212] [S144]

当前最多 8 个 internal hostnames，仅 HTTP port 80，不支持 HTTPS／WebSocket，dev server 的热更新连接也不会因此可用。普通 hostname guardrails 不检查 internal hosts；可用 `allowedDomains: []` 只允许内部站点，但应用仍须限制目标端口、路径和可读数据。[S144]

**停止对话会取消浏览器调用吗？** 当前文档及 Pi 1.5 公告已改变旧边界：Pi、AI SDK 和 TanStack AI adapter 接到 harness abort 时，等待 tab 的调用退出，运行中的调用以错误结束并释放 tab。已经点击、提交或产生的浏览器动作仍然存在。不能把本书 10 月 20 日记录的“不取消已运行调用”继续当作新版本行为，也不能把现在的取消当作事务回滚。[S209] [S144]

Browser Run 10 月 30 日默认更新到 **Chrome 152**，Quick Actions 的默认 User-Agent 随之改变；按 UA 放行的站点要检查匹配条件。`/links` 返回 absolute URLs，Markdown 保留代码语言；11 月 3 日 `/crawl` 另加每个 URL 的 `outcome`，及最多 50 个 origin 的 robots.txt 诊断。任务完成、某个 URL 成功与是否被 robots 拒绝可以分别判断。[S220] [S221]

<!-- chapter: skills -->

## 05 / Skills 进入文件系统，迁移不能只换 import

10 月 29 日，Agent Skills 改由 Workspace、R2 或代码三种来源加载；Think 每轮重新列出来源，`/workspace/.agents/skills/` 下的 `SKILL.md` 可在下一轮使用，不需重新 build／deploy。要求 Agents SDK **0.32.0+**、Think **0.23.0+**。[S210]

直接使用旧 `agents/skills` 的程序有 breaking changes：`agents:skills` Vite import、compile、`SkillRegistry`、Think `skillWorkspace` 已移除，`runner()` 移到 `agents/skills/runner`。部分格式违规会带 warning 加载，缺 description 或不可用的 frontmatter 等仍会跳过；不能把成功加载当成严格校验通过；写入前可用 `parseSkill()` 检查。来源可更新也不等于取得额外工具权限，Workspace 脚本仍受实际执行环境和应用授权控制。[S210] [S211]

<!-- chapter: gateway -->

## 06 / 新 Gateway 必须认证，alias 也没有缩小 token 范围

11 月 3 日起，新建 AI Gateway 强制认证；创建时省略 `authentication` 等于 `true`，显式 `false` 返回 `400`。旧的未认证 gateway 可继续原设置，但一旦开启就不能再关。启用前先准备 HTTP 客户端凭据；Workers binding 保持预认证。[S213]

REST `/ai/run` 用标准 `Authorization`，`gateway.ai.cloudflare.com` 的 provider-native endpoints 用 `cf-aig-authorization`。AI Gateway 的 Read／Run／Edit token 是 **account-scoped**，不能只限制到单个 gateway；有 Run 的 token 可使用该账户其他 gateway 及其已存 provider keys。不同 alias 名称不构成租户隔离。[S214]

11 月 4 日 model alias 用 `custom/<name>` 表达 gateway 内的一组模型，可按顺序 fallback 或 smart routing；REST 请求用 `cf-aig-gateway-id` 选择所属 gateway。配置更新可能暂时命中缓存，输入格式和可用 provider 仍须兼容；需要条件分支、百分比分流或流程内限制时，仍看 dynamic routes。[S215] [S216]

这提供了无需重部署应用即可调整模型池的路线，没有替本书的 Clef／Jev 比较重新测性能或改价格。调用与管理权限、网关准入与模型输入分别核对，见[模型接入页](../services/decision-models.md)。

## 07 / 11 月 17 日默认值取决于 compatibility date

11 月 2 日的两则公告都针对 `compatibility_date >= 2026-11-17`。保留旧日期和 flags 的 Worker 不会因为日历翻到 17 日就自动切换。[S217] [S218]

| 默认变化 | 升级前检查 |
|---|---|
| JavaScript Worker 启用新 module registry | 无效 import attributes 会被拒绝；`require()` 载入 ES module 时，模块及依赖不能用 top-level `await`；Python 继续 legacy registry。需暂留旧行为时用 `legacy_module_registry` |
| `request.signal` 收到客户端断开 | 主动把 signal 传给支持取消的操作；此次不启用 `request_signal_passthrough`。需 opt out 时用 `disable_request_signal` |

提前试用可在原日期下分别开 `new_module_registry`、`enable_request_signal`。断开通知不是任意外部服务的停止确认，已有副作用要独立核对。仓库的离线例子和发布模板没有为追新而改 compatibility date。

## 08 / D1 的 50 MB 是查询结果上限

10 月 30 日公告指定 **11 月 4 日**起强制最大查询结果 **50 MB**，超出会返回 `D1 query result exceeded the maximum response size limit of 50 MB`。它不是数据库容量；REST 的 import／export 不受此项查询结果上限约束。[S219]

先减少选出的列、分批查询并检查后页失败；不能把一次大结果失败写成数据丢失，也不能只取首批就宣布盘点完整。D1 undelete 的七天窗口与 Time Travel 仍按各自条件阅读。本轮未查询真实数据库。[S219]

## 09 / 私有 IP 回源，仍先核对账户与网络路径

10 月 30 日博客宣布 private origins 的 public-to-private 路线 GA：proxied A／AAAA 指向私有 IP，经已有 Cloudflare One 连通性回源，WAF、缓存、规则与 Workers 仍在应用服务路径上。机制文档当前标题仍标 beta；本书并列保留这个状态差异，不推定所有账户无需申请即可用。[S226] [S227]

实际前提仍包括 Private Origins entitlement、目标位于 **default virtual network** 的可达路由；WAN／Mesh 另需 Unified Routing 和回程路由，Tunnel 不需要这两项。Argo Smart Routing、Dedicated CDN Egress IPs 和 Zero Trust network session logs 有限制，健康检查需要 Load Balancing。WAN 加 Tiered Cache 的 cache miss 还可能在 upper tier 返回 403，按文档先判断并针对受影响 hostname 处理。[S227]

同一时期 VPC Network binding 可以用 `cf1:vnet:<UUID>` 选择其他 virtual network；这不能反推 private origins DNS 已支持同样选择，也不能把两条路线的地点、权限或计划条件合并。[S225] [S227]

这轮没有配置私网、DNS 或 Access。已有服务器和 Tunnel 路线继续保留，新增能力只在具体需求与账户条件命中时重评。

## 10 / 发布证据、资源前缀与本地默认值

Workers Builds 的 build 与 build logs 在完成后保留 **90 天**，之后删除；它们产生的 versions／deployments 仍在版本历史。需要长期保存的调查证据应另行导出，不把旧日志入口当成永久凭证。[S223]

Workers Static Assets 新增 `assets.base_path`，不用移动目录即可挂到 `/blog` 之类的前缀；要求 Wrangler **4.148.0+**，cf 对应 `worker.assets.basePath` 与 **1.0.0-beta.13+**。这不能自动修复 HTML 的 absolute links；用前缀后的实际页面、原文下载和 404 再验收。本书资料架仍按根路径模板发布，不改现有配置。[S222]

Flagship binding 本地开发默认改为 local flag store，起初为空、返回代码给的默认值；需要远端求值须显式 `remote: true`。本地 store 要 Wrangler **4.135.0+** 或 Vite plugin **1.56.0+**，Local Explorer 管理另要 **4.148.0+／1.63.0+**。本地求值不再证明远端旗标已生效。[S229]

## 11 / 标签参与授权，指标拆分帮助定位

Access Service Token 每个最多 5 个 key-value tags；`Service Token Tag` selector 按精确 key／value 匹配有效 token，可在 Service Auth policy 中按环境或团队放行。修改标签现在可能改变可访问应用，不能再仅当作整理备注；应用内资源权限仍单独验证。[S224]

R2 bucket Metrics 可按地区比较读、写、错误和 429，再按 HTTP 状态码调查；地区指标帮助找异常，不等于数据存储地点或 jurisdiction 的证据。[S228]

其他本期信号包括个人 agent 访问策略、私网负载均衡 affinity、Audit Logs v2 account analytics、SCIM population viewer、Browser Isolation 只读键盘、Zero Wire 与 WAF 规则更新。本轮发现但未扩写为配置教程；相关账户、计划、漏洞适用性及设备版本须另查，不据此推荐统一升级或改策略。

## 12 / 这轮更新到哪里

本期把费用延期、恢复与取消、认证和私网条件接回当前解释，并登记公告日与明确的生效日。11 月 17 日两项 compatibility 变化和 12 月 1 日计费仍是后续复核点；可以用 `fieldbook.py window` 查看登记的日期窗口，但该命令不发现新公告，也不替人裁定适用性。

局部查阅不推迟尚未复核材料的原期限。Artifacts 的 10 月 14／15 日旧说法与现价页 11 月 12 日起点、Clairic 的 context／pass 疑点仍分别阅读，没有用新报告日期掩盖。来源审阅、离线检查、网页显示与云端实测各自成立；本轮没有新 PDF Release、模型调用、账户变更或云端恢复实验。
