# Cloudflare 新发布观察 · 2026-10-20

这一轮更新关心四件具体的事：原文里有的中文为什么搜不到，通知中的字段怎样取回原文，agent 停下以后哪些操作仍在运行，以及请求到底经过了哪个检查点。费用与时间条件也一起核对；当前主题页承接使用说明，本篇保留 10 月 20 日的观察位置。此前报告与固定出版物不因今天的来源变化回写。

## 02 / 中文检索先检查切词、匹配模式与索引

10 月 16 日，AI Search 修复 `trigram` 对无空格中日韩问句的处理。官方建议中日韩内容使用 `indexing_options.keyword_tokenizer: "trigram"`，切换会全量重建。它按三个字符的重叠窗口匹配，**两字名字仍不能独立命中**；多项查询默认 `and`，改 `or` 会改变召回。[S161] [S162]

[检索页](../services/search.md#中文明明在原文里为什么搜不到)现在提供长中文问句、两字人名、代码标识、语义改写和无答案五组合成样本。比较 keyword 与 hybrid 时固定原件和期望证据，先核对入库、分块与重建状态，再决定是否换 embedding；本书没有把样本设计写成已跑出的成绩。

Workers Paid 开启 keyword 的实例上限为 500,000 文件，vector-only 为 1,000,000。11 月计费后，超额 full-text 查询 $0.10／千次，semantic／vector／hybrid $0.75／千次。内部 Workers AI embedding 与 reranking 已包含，生成、query rewriting 与外部模型另计；成本比较要同时看每题查询次数和后续调用。[S162] [S10]

## 03 / 抽取字段，是有限决策以外的输出空间

10 月 19 日 preview 的 Clairic 接收材料与字段 schema，返回 typed values，包括原文片段、数字、日期和列表。Clef／Jev 从预先列出的选项里选择；Clairic 则可以取得事前无法枚举的版本号、时间与错误代码。通用生成模型继续负责解释、代码与开放式推理。这个边界补入[模型页](../services/decision-models.md)，[Clef／Jev 专题](../comparisons/clef-vs-jev.md)仍以有限决策比较为主。[S163] [S165]

Clairic 标价 $0.10／百万输入 tokens，无生成输出 token 费。类型合法不等于内容正确；首轮设计使用短部署通知，核对缺失字段、尾部证据、原文位置、`truncated` 与返回用量。复杂计算宜抽取输入后交给代码，而不是用结构化外壳替代正确性检验。[S163] [S164]

同一模型页仍分别写 **65,536-token context** 与 **8,192-token pass**，关系没有解释清楚。字段可拆多 pass，不能只按原文长度推算总费用，应记录 `usage.input_tokens`／`usage.passes`。这处疑点进入登记，未据此承诺大窗口完整读取。[S164]

通用生成路线另有 DeepSeek V4.1 Flash 1017：模型卡为 1,048,576 context，输入 $0.30／M、输出 $1.20／M、缓存输入 $0.006／M，需要 Workers Paid 或预付 AI Gateway credits。它进入模型页短条目，没有与决策／抽取模型混作同任务排名。[S170] [S171]

## 04 / 浏览器存活、任务停止和追加权限分别处理

Agents SDK 的 Browser／browserTool [S144] 可以保留仍然存活的远端浏览器，DO 休眠后按 session 身份重连；默认空闲保活 10 分钟，过期或崩溃会丢失 tabs、cookies 和登录态。不同 tab scope 也不等于不同登录 profile。Pi 不自动重放被中断的浏览器调用；停止对话不取消已开始的调用，需等完成或超时。当前说明进入[Agent runtime](../services/agent-runtime.md)。

Workers Issues → MCP Events [S145] 可用签名 webhook 触发新问题／复发问题调查，前提是启用 Issues、相应权限与客户端兼容。MCP step-up [S146] 则在缺少 scope 时返回 `insufficient_scope`，由支持的客户端请求用户追加授权。事件提供线索，工具读回证据，后续动作需要权限时再授权；工具报错本身不能授予权限。

## 05 / 云 API 与 HTTP 出站控制有不同检查点

本轮新增[出站控制主题页](../services/egress-controls.md)。Cloud Workload Security Beta [S151] 在用户运行的代理中按云 API 操作与参数执行过滤／Rego 检查；Zero Trust Free 可满足订阅要求，代理运行成本仍由使用者承担。客户端须实际使用代理并信任 CA，未分类目的地可能直接走 tunnel；创建策略和连接成功都不足以证明某项请求政策执行。

Gateway Forward public beta [S156] 则在进入 Gateway 的 HTTP 流量中选择 Worker，适用于所有 Zero Trust plans，Workers 用量正常计费。HTTPS 需要解密；WebSocket、CONNECT 与 Do Not Inspect 不经过该 Worker。`next()` 只能零或一次，保留原目标；普通 Worker `fetch()` 是独立子请求，不应推定继承用户的 Gateway 路径。

发布博客展示了 DLP 后接 Worker 的应用方向，当前接口文档却明确：DLP／body inspection 结果不能作为选择 Worker 的条件。[S158] [S156]Worker 可能先开始，body 拒绝还能中断它；新流程图据此区分调用、检查和实际出站。这是机制说明，没有配置真实代理或 Gateway。

## 07 / 从新来源回到维护正文

官方 `cf docs search` 提供实时文档入口，再读取原页核对条件。源码在 beta.15 已登记这项能力，10-16 公告介绍 beta.16；beta.16 也统一部分命令为 kebab-case。查询无需 Cloudflare 登录，但 changelog 明示会记录查询 telemetry，不要输入私人材料。[S149] [S150] [S160]版本与读取流程进入[API 维护](../reference/api-maintenance.md)及[贡献说明](../CONTRIBUTING.md)。

本轮再次按“来源 → 数据 → 当前表格 → 表外说明”维护 Observability。`impact-source` 与 `impact` 给候选范围，`due` 只查登记复核日；它们都不能自动判断新公告或项目适用性。整份 launches 依赖仍可能带出无关候选，本次人工核对，没有借内容更新重建维护系统。

本篇只记录公开来源查阅和编辑判断。查询样本、请求形状与路径图不是云端实验结果，源更新、离线检查、网站发布与 PDF Release 也分别记录。
