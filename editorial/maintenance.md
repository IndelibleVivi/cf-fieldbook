# 持续参考仓库提案

## 它值得长期存在的原因

发布信息、实施经验和运行现场的保质期不同。发布信息要保留当时的条件；手册要随行为变化修订；运行现场属于实际账户，不宜混进公开文件。一个仓库可以把前两者接起来，又不变成第三者的影子数据库。

读者应该能从一个新名称找到四件事：它具体做什么，现在怎样获得，付费单位是什么，第一次试验怎样得知它是否有用。接手实施的 agent 则应该能找到准确来源、适用日期、示例边界与需要补的验证，不能把一篇介绍当作部署授权。

## 三条主线，不设强制流水线

**按期报告。** 每篇有覆盖窗口、核验日、关键差异、费用变化与判断依据。发布后以新版本或勘误修改，不无声改写历史。

**持续手册。** 围绕任务组织：发布一个站点、保护已有服务、保存内容、恢复任务、做检索、运行隔离计算。一个产品可以出现在多个任务中，不要求读者先掌握整张产品地图。

**可复验的小实验。** 只有反复影响理解的行为才进入代码。例如登记不等于完成、迟到任务不能覆盖新状态、按单位估算费用。示例应能独立运行；纯本地、模拟平台、真实云端三种证据分别标注。

## 本期的目录已经足够

已有 `reports/`、`guides/`、`catalog/`、`examples/`、`tests/`、`editorial/`、`templates/`、`tools/`、`styles/` 与 `dist/`。暂不增加数据库、MCP、后台服务、多用户账号、向量搜索或自动生成新闻站。两份文件可以先证明阅读价值。

`catalog/launches.json` 是精选重要条目的编辑登记，不承诺收齐平台所有公告。缺失的精确发布日期用 null，不能从网页抓取日期反推。资格、价格与状态不同步时用独立字段记录。

## 一次更新怎么做

从官方发布页、产品 changelog 和已引用文档开始，只深读可能影响读者决策的变化。优先处理收费、生效日期、权限、数据持久性、弃用和迁移；纯宣传性重复不构成一篇新报告。

读到新条目后，对比原记录，写清哪项判断改变。一个“GA”公告不自动把所有相关 SDK、托管版和地区都升级为 GA。价格变化核查计量单位、共享范围、日期和免费部分，不只替换一个美元数字。

再决定落在哪里：只适用于当期的放报告；改变实施步骤的修改手册；容易重复讲错的增加例子和测试；尚不能确认的写待核验项。最后重建两种格式，检查来源链接、目录、表格分页和分享边界。

## 信息登记只需这些字段

| 字段 | 用途 |
|---|---|
| `announced_on` | 官方实际发布日期；不确定则 null |
| `verified_on` | 本次确实核验的日期 |
| `status` | GA / beta / preview / waitlist 等具体状态 |
| `access` | 套餐、地区、申请或其他前提 |
| `effective_events` | 未来收费、维护结束等事件，独立于发布日期 |
| `sources` | 可打开的原始依据编号 |
| `conflicts` | 两份来源不一致时，各写什么 |
| `next_check` | 下一次需要确认的具体问题，不是自动承诺 |

这个登记表是索引，不是平台事实的替代品。长篇解释继续放 Markdown；不把所有判断塞进 JSON 枚举。

## 当来源冲突时

保留两边的说法与来源，不随意挑一个听起来更合理的版本。预算可以按较早收费日期保守规划，但应把“规划采用”与“官方事实”分开。未来冲突解决时注明采用的新依据，旧期报告增加勘误。

本期已有例子：Artifacts 价格页与发布博文的起算日相差一天。这样的分歧值得进入持续资料，而不是被排版抹平。

## 自动化到哪里停止

合适的自动化是检查引用、提醒某个日期将到、生成差异草稿、重建 PDF。尚不适合自动完成的是：从 beta 宣传推断生产可用、替读者选择许可、自动开通收费资源、发布没有核验的价格和性能结论。

以后要接定时任务，可以先只生成“发生了什么变化、影响哪份材料”的候选清单。是否发报告、是否修改手册由编辑决定。本包没有配置定时任务。

## 对外分享与署名

公开入口需要明确编者署名、可转发方式、修改后的标识和第三方材料权利。仓库拥有者应选择文字与代码的许可；本文不代选。公开可见、已经脱敏和准许任意再许可不是同一件事。

对于历史私人资料，只保留被授权公开的机制总结，不复制访问链接、身份、真实拓扑或受限原件。贡献者以后提交实际故障案例时，也应使用合成输入与可说明的版本条件。

## 可以逐步长出来的部分

使用一段时间后，若来源卡反复需要相同格式，可以增加校验；若教程很多且读者难找，可以做静态站；若多个产品组合的恢复流程难懂，可以补可交互实验。每次扩建都应来自已出现的阅读或实践问题，不把目录数量当作成熟度。

## 阅读版 2 的补充

`reference/` 保存更直接的技术实施材料，`reports/` 与 `guides/` 优先服务人的理解。两层共用来源与示例；不能为了“给机看”另造一套与读者版矛盾的事实。

当前署名使用 Faye & Cove；GitHub 单独放明确地址，读者文末为 `made by Faye & Cove`。视觉维持白底 Cyan × Orange，实际项目启发保留为可选情境。更新不需要自动扩展到个性化架构咨询或每个产品的完整示例项目。
