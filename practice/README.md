# 实践记录：从真实问题看服务怎样配合

网页能打开、上传已经返回、连接器显示健康，都是有用的线索。但它们各自只说明一段路径。下面三篇来自作者维护过的系统，保留实际遇到的问题、当时的修复和验收范围，帮助你判断下一步应该检查哪里。

## 01 / 私有资料阅读站

想让受邀读者看资料，又不想让自己的电脑一直开着。把本机编辑与云端交付分开，在新内容完整可读以后切换版本；语义搜索找到候选，读取时仍然检查权限。

[电脑关机以后，读者仍能阅读 →](private-reader.md)

## 02 / Access 与 PWA 重连

手机 PWA 还显示页面，操作却失败，重新登录也没恢复。一次真实故障揭开了缓存外壳、Access 会话与应用版本的区别，也解释为什么要保留真正走网络的重连路径。

[页面还在，连接已断 →](access-pwa.md)

## 03 / 受保护的状态页

状态页入口能要求登录，怎样判断服务是否真的正常？保留原应用与 Tunnel 的分工，分别观察入口、源站和实际登录后的页面。

[把门禁和健康分开检查 →](protected-status.md)

## 继续阅读与来源

可以按眼前的问题直接进入，不必把三种组合一起部署。[手册](../guides/handbook.md)给出更广的服务选择；[离线例子](../examples/README.md)让你先在合成输入上观察一个机制。

这些是匿名重构的历史实践，观察日期在各篇内标明。原项目身份、真实材料和配置没有进入本文。官方链接解释平台与浏览器的通用机制，日期表记录作者当时实际观察到的行为；2026-10-03 编辑时没有重新登录这些系统或进行新的云端实验。它们不是当前在线状态报告，也不是一套可直接部署的配置包。

三篇都围绕同一个可复用的问题：**这条证据究竟证明了哪一段，接下来怎样检查尚未经过的那一段？**
